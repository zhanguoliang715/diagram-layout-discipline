# 技能说明 · diagram-layout-discipline（图表排版纪律）

## 一句话

画 SVG 图表时**不许出三类低级错误**：文字溢出边框、嵌套容器分不清、流程用文字描述。

## 什么时候用

- 要做一张给人看的图（架构图、流程图、对比图）；
- 图要插进 Word / PPT / 网页，字号会被缩放；
- 之前做的图被反馈"文字糊成一团""这框套那框看不出来"。

**不适用**：纯装饰性插画、需要美术风格的图。这是"结构图不画错"的纪律，不是设计美学。

## 为什么需要纪律

三条规则都来自被退回的实例，不是凭感觉定的：

| 现象 | 根因 | 规则 |
|---|---|---|
| 子框露到父框外面 | 容器高度手填，算错了 | **坐标必须由代码计算**，容器高度由子框反推 |
| 文字压到边框上 | 汉字宽度靠眼睛估，估计必然偏小 | **文字宽度必须实测**（`scripts/measure_text.py`） |
| 两层框看不出从属 | 内外层用了同一色相近档 | **描边 RGB 距离须 > 150** |
| 七步流程写成一段话 | 图能表达的用了文字 | **有先后 / 分支 / 层级 / 数量的，必须画图** |

## 它怎么做

1. **改骨架，不从零手写**：`scripts/gen_skeleton.py` 里已有 `text()`（自动断言不溢出）、`parent_child_ok()`（断言包含关系）、`dist()`（断言色距）、`box()`。把数据填进去，坐标让它算。
2. **跑断言**：生成时逐条检查，通过才输出 SVG。
3. **做破坏性实测**：故意把容器高度改小，确认断言会报错，再改回来——**没报错的断言等于没接**。
4. **按成稿字号反推**：图会被缩放进文档，画布像素要换算成等效 pt，太小的字号在纸上是糊的。

## 边界

- **只管结构图**，不管插画、摄影、UI 视觉。
- **不能替代审美判断**：断言保证不压边、不混淆，不保证好看。
- 断言的度量依赖字体文件，**换字体后要重量一遍**。

## 怎么验

```bash
cd skills/diagram-layout-discipline/scripts
python gen_skeleton.py    # 退出码 0 且打印「全部通过」才算数
python gen_all.py         # 四张示例图 + 三类断言
```

需要 `Pillow` 量字宽。断言失败时会指出是哪个元素、超了多少像素。

## 最常见的三个错

1. **眼睛估宽度**。汉字 12px 宽≈12px，拉丁字母≈6.5px，凭感觉估窄了 20% 很常见。
2. **用 `getbbox()[2]` 当文字宽度**。它含左侧 bearing，会偏大；要用 `font.getlength()`。
3. **断言从来没跑失败过**。这说明判据可能压根没生效，需要造一个坏样本试。
