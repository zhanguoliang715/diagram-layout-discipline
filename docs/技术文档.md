# 技术文档 · diagram-layout-discipline

**定位** SVG 结构图的排版纪律与断言工具（独立技能）｜**运行时** Python 3.9+，无第三方依赖

## 1. 定位

不是画图工具，是**画图的验收标准**。它约束三件可机器判定的事（溢出、包含、色距）与一件需人判断的事（该不该画图）。

## 2. 输入契约

| 项 | 要求 |
|---|---|
| 画布 | 固定宽度（示例 680 / 1900），高度由内容算 |
| 元素 | 矩形（容器与节点）+ 文本（每个 `<text>` 都要有归属框） |
| 配色 | 同一图内描边色两两 RGB 距离 > 150 |
| 字号 | 按成稿字号反推，不是按画布像素拍脑袋 |

## 3. 输出契约

- SVG 源码（内联交付，不默认导 PNG）
- 生成时的断言结果：全部通过才输出，任一失败则指出元素与超出量

## 4. 断言逻辑

| 断言 | 函数 | 判据 |
|---|---|---|
| 文字不溢出 | `text()` | 起笔 x + 实测宽 ≤ 框内侧右界 |
| 子框在父框内 | `parent_child_ok()` | 含 ≥20px 内缩 |
| 描边可区分 | `dist()` | 两色 RGB 距离 > 150 |
| 容器高度自洽 | 由子框反推 | `parent_h = 最后子框 bottom + 内缩 − parent_y` |

`measure_text.py` 的宽度模型：中文 ≈1.00em、拉丁 ≈0.55em、空格 ≈0.28em，**刻意高估**。

### 已知限制

| 限制 | 后果 | 缓解 |
|---|---|---|
| 宽度是估算而非字体度量 | 与具体字体有偏差 | 高估策略兜住绝大多数情况；要求精确时用 PIL 的 `font.getlength()` |
| 不校验字号可读性 | 断言通过但字太小 | 按等效 pt 反推（画布像素 × 插入宽 ÷ 2.54 × 72 ÷ 画布宽） |
| 色距只算 RGB 欧氏距离 | 不等于人眼感知可分辨 | 150 是经验下限，仍建议换色相而非只拉明度 |
| 无法判断"该不该画图" | 该画的没画、不该画的画了 | 靠人的判据：有先后/分支/层级/数量才画 |

## 5. 能力边界

**能做**：约束结构图不溢出、不混淆、坐标自洽；提供可复用骨架。

**不能做**：插画与视觉设计、自动排版优化、感知级配色评估、跨字体精确度量。

## 6. 设计取舍

| 选择 | 为什么不选另一条路 |
|---|---|
| 坐标全部由代码算 | 手填必错，且错了不可复现地错 |
| 宽度刻意高估 | 漏报导致返工，误报只多量一次 |
| 内联 SVG 而非导 PNG | 可直接嵌文档/网页，缩放不失真 |
| 断言必须在生成时跑 | 事后检查依赖人的自觉，等于没有 |

## 7. 优缺点

**优点**：零依赖；错误在生成阶段暴露而非交付后；骨架可复用，避免每次重踩同一坑；判据明确可争辩。

**缺点与缓解**

| 缺点 | 影响 | 缓解 |
|---|---|---|
| 估算宽度有偏差 | 极端字体下仍可能溢出 | 留 8–10% 余量；关键图用真实字体度量 |
| 断言只覆盖几何 | 语义错误（框放错位置）不报 | 人工复核一次成图 |
| 学习成本 | 需要读骨架代码 | 提供 `gen_all.py` 作可运行范例 |

## 8. 失败模式与处置

| 现象 | 根因 | 处置 |
|---|---|---|
| 断言全过但图仍被指溢出 | 字体与估算差异大 | 换真实度量，或加宽框/缩短文案 |
| `parent_child_ok` 报某框未包含 | 容器高度手填 | 改由子框反推，不要直接改高度数字 |
| 色距断言报冲突 | 内外层用了同色相相邻档 | 换色相或拉开明度，不要只调透明度 |
| 断言从不失败 | 判据未接上 | 造坏样本（把高度改小）验证它会报错 |

## 9. 与其他技能的关系
